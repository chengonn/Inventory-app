# 內部庫存管理系統 — Codex 實作規格（雲端版 V2）

版本：V2  
定位：單人內部庫存管理、電腦與手機皆可使用、不依賴個人電腦持續開機  
技術：Next.js + TypeScript + Vercel + Supabase PostgreSQL + Supabase Auth

---

# 0. 文件目的

本文件取代 V1「Windows 本機 Server + SQLite + LAN」架構，作為 Codex 後續實作的 source of truth。

V2 的核心目標：

- 系統部署到雲端，不需要使用者的 Windows 電腦持續開機。
- 電腦與手機可透過 HTTPS 網址操作。
- 僅供一位內部使用者使用。
- 不提供公開註冊。
- Excel 仍保留為初始資料匯入、匯出與人工備份工具。
- 正式資料以 Supabase PostgreSQL 為唯一資料真相。
- 所有庫存異動必須可追溯，不可直接刪除歷史交易。

V1 中以下內容全部作廢：

- SQLite / `inventory.db`
- Windows 主機當 Server
- `0.0.0.0` LAN Server
- 手機必須同 Wi-Fi
- Windows Firewall 開 Port
- SQLite 檔案複製式備份
- 自製單一 PIN 登入

# 2. 三個主要風險與處理方式

## 2.1 公司資料上雲

風險：庫存、櫃位、領用紀錄會離開本機環境。

處理：
- 上線前確認公司是否允許將此類資料存放在第三方雲端。
- 不上傳與庫存管理無關的敏感檔案。
- 不把 Service Role Key、DATABASE_URL、密碼寫入 Git。
- 使用 Vercel Environment Variables。
- `.env*` 加入 `.gitignore`。

## 2.2 Serverless + Prisma 連線管理

風險：錯誤使用直接 DB connection 可能造成 serverless 連線數過多。

處理：
- Production runtime 使用 Supabase Supavisor transaction pooler。
- Migration / Prisma CLI 使用適合 migration 的 direct/session connection。
- 將 runtime 與 migration connection 分開設定。
- Prisma Client 只能在 server-side 使用。

建議環境變數：

```text
DATABASE_URL=Supavisor transaction pooler URL
DIRECT_URL=Supabase direct 或 session-pooler URL（供 migration）
```

Codex 實作前需依當前 Supabase + Prisma 官方文件確認連線格式，不可猜 port 或 query parameter。

## 2.3 系統公開在 Internet

風險：網址可從 Internet 存取，不能再用簡單 PIN 保護。

處理：
- 使用 Supabase Auth Email + Password。
- 禁止公開 signup UI。
- Database 只允許 server-side Prisma 存取業務資料。
- 所有 protected routes 必須驗證登入狀態。
- 未登入請求 redirect `/login`。
- 不把 Supabase service role key 暴露到 browser。

必須保留的規則：

1. 先建立品項主檔，再做交易。
2. 同一品項可存在不同櫃位。
3. 入庫、出庫、盤盈、盤虧都新增歷史，不覆蓋舊資料。
4. 錯誤交易以 reversal 更正，不直接刪除。

7. `1羅裝`、`1囖裝`、`500cc（用了3/4）` 等資料不可硬換算為 0。

# 5. Supabase 專案規則

## 5.1 Database

使用一個 Supabase project。

正式資料表由 Prisma migration 管理，不在 Dashboard 手動修改 production schema，除非為緊急維修且之後補 migration。

## 5.2 Auth

使用 Supabase Auth：

```text
Email + Password
```

需求：
- 系統沒有 signup 頁。
- 初始帳號由管理者在 Supabase Dashboard 建立或用安全的 bootstrap 流程建立。
- App 只允許白名單使用者登入。
- 第一版預設只允許 1 個 email。

建議環境變數：

```text
NEXT_PUBLIC_SUPABASE_URL=
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=
ALLOWED_USER_EMAIL=
```

若需要 server-only admin operation，才使用：

```text
SUPABASE_SERVICE_ROLE_KEY=
```

Service Role Key：
- 只能 server-side。
- 不得使用 `NEXT_PUBLIC_` 前綴。
- 不得回傳給 browser。
- 非必要不要使用。

## 5.3 Session

- 使用 Supabase Auth session/cookies。
- Protected pages 在 server-side 驗證 session。
- 未登入 redirect `/login`。
- 已登入訪問 `/login` 時 redirect `/dashboard`。
- Logout 後清除 session 並回 `/login`。

# 10. 庫存計算模型

不可建立 `Item.currentQuantity` 作唯一真相。

現有庫存：

```text
OpeningInventory（CONFIRMED）
+ StockMove signedQty（CONFIRMED）
= Current Stock
```

最小計算維度：

```text
Item + Location
```

品項總庫存：

```text
SUM(all locations for item)
```

`NEEDS_REVIEW`：
- 不計入 normalized stock。
- 可在待確認頁修正後變 `CONFIRMED`。

# 11. 入庫流程

```text
/moves/in
```

```text
選品項
  ↓
選櫃位
  ↓
輸入數量
  ├─ 直接標準數量
  └─ 容器方式
      ├─ 容器類型
      ├─ 容器數
      ├─ 每容器數量
      └─ 零散數量
  ↓
預覽換算結果
  ↓
填寫經手人／單據／備註（可選）
  ↓
確認
  ↓
Server-side transaction
  ↓
新增 StockMove(IN)
  ↓
顯示完成結果
```

公式：

```text
normalizedQty = containerCount * unitsPerContainer + looseQty
```

若有容器但不知道每容器數量：

```text
status = NEEDS_REVIEW
normalizedQty = NULL
signedQty = NULL
```

# 12. 出庫流程

```text
/moves/out
```

提交前顯示：

```text
目前：40 支
本次：5 支
剩餘：35 支
```

預設：
- 禁止 confirmed stock 出庫後 < 0。
- 若資料本身為 NEEDS_REVIEW，不能用其未知數量支撐出庫。

成功：

```text
type = OUT
normalizedQty = 5
signedQty = -5
```

Concurrency：
- 出庫庫存檢查與 INSERT 必須放在 server-side transaction。
- 不可只相信前端顯示的 current stock。

# 14. 異動與更正

`StockMove` 不可 hard delete。

錯誤交易：

```text
原交易
  ↓
建立 reversal
  ↓
必要時建立正確的新交易
```

Reversal 必須：
- 指向 `reversalOfMoveId`。
- signedQty 為原交易相反值。
- 不可對同一交易重複 reversal，除非明確設計並有測試。

- 補齊換算資訊。
- 重新計算 normalizedQty。

## 16.1 防重複

`ImportBatch.fileHash` 使用 SHA-256。

相同 hash：
- 預設禁止再次 commit。
- Preview 可以顯示「此檔案已匯入」。

## 16.2 安全要求

- 限制 `.xlsx`。
- 限制檔案大小，例如 10 MB，可配置。
- 在 server-side 解析。
- 不信任 workbook 內公式結果。
- 匯入前必須做 schema validation。
- commit 失敗時整批 rollback。

# 18. Prisma Schema V2

以下為業務模型基準。Codex 可依最新 Prisma 語法調整 datasource/config，但不可改變業務語意。

```prisma
enum MoveType {
  IN
  OUT
  ADJUST_GAIN
  ADJUST_LOSS
  REVERSAL
}

enum DataStatus {
  CONFIRMED
  NEEDS_REVIEW
  IGNORED
}

model Item {
  id          Int      @id @default(autoincrement())
  name        String
  unit        String?
  safetyStock Decimal? @db.Decimal(18, 3)
  note        String?
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  openingInventory OpeningInventory[]
  moves            StockMove[]

  @@index([name])
}

model Location {
  id          Int      @id @default(autoincrement())
  area        String
  cabinetNo   String
  displayName String?
  note        String?
  isActive    Boolean  @default(true)
  createdAt   DateTime @default(now())
  updatedAt   DateTime @updatedAt

  openingInventory OpeningInventory[]
  moves            StockMove[]

  @@unique([area, cabinetNo])
}

model OpeningInventory {
  id                Int        @id @default(autoincrement())
  itemId            Int
  locationId        Int
  rawQuantityText   String?
  containerType     String?
  containerCount    Decimal?   @db.Decimal(18, 3)
  unitsPerContainer Decimal?   @db.Decimal(18, 3)
  looseQty          Decimal?   @db.Decimal(18, 3)
  unit              String?
  normalizedQty     Decimal?   @db.Decimal(18, 3)
  status            DataStatus @default(CONFIRMED)
  sourceSheet       String?
  sourceCell        String?
  note              String?
  importBatchId     Int?
  createdAt         DateTime   @default(now())

  item        Item         @relation(fields: [itemId], references: [id])
  location    Location     @relation(fields: [locationId], references: [id])
  importBatch ImportBatch? @relation(fields: [importBatchId], references: [id])

  @@index([itemId, locationId])
}

model StockMove {
  id                Int        @id @default(autoincrement())
  moveNo            String     @unique
  occurredAt        DateTime
  type              MoveType
  itemId            Int
  locationId        Int
  rawQuantityText   String?
  containerType     String?
  containerCount    Decimal?   @db.Decimal(18, 3)
  unitsPerContainer Decimal?   @db.Decimal(18, 3)
  looseQty          Decimal?   @db.Decimal(18, 3)
  unit              String?
  normalizedQty     Decimal?   @db.Decimal(18, 3)
  signedQty         Decimal?   @db.Decimal(18, 3)
  status            DataStatus @default(CONFIRMED)
  operator          String?
  documentNo        String?
  note              String?
  reversalOfMoveId  Int?       @unique
  importBatchId     Int?
  createdAt         DateTime   @default(now())

  item        Item         @relation(fields: [itemId], references: [id])
  location    Location     @relation(fields: [locationId], references: [id])
  importBatch ImportBatch? @relation(fields: [importBatchId], references: [id])

  @@index([itemId, locationId, occurredAt])
  @@index([occurredAt])
}

model ArchivedRecord {
  id                Int      @id @default(autoincrement())
  removedAt         DateTime?
  area              String?
  cabinetNo         String?
  itemName          String
  rawQuantityText   String?
  containerType     String?
  containerCount    Decimal? @db.Decimal(18, 3)
  unitsPerContainer Decimal? @db.Decimal(18, 3)
  looseQty          Decimal? @db.Decimal(18, 3)
  unit              String?
  normalizedQty     Decimal? @db.Decimal(18, 3)
  originalStatus    String?
  sourceCell        String?
  removalReason     String?
  note              String?
  importBatchId     Int?
  createdAt         DateTime @default(now())

  importBatch ImportBatch? @relation(fields: [importBatchId], references: [id])
}

model ImportBatch {
  id             Int      @id @default(autoincrement())
  fileName       String
  fileHash       String   @unique
  importedAt     DateTime @default(now())
  itemCount      Int      @default(0)
  inventoryCount Int      @default(0)
  moveCount      Int      @default(0)
  reviewCount    Int      @default(0)

  openingInventory OpeningInventory[]
  moves            StockMove[]
  archives         ArchivedRecord[]
}

model AuditLog {
  id         Int      @id @default(autoincrement())
  action     String
  entityType String
  entityId   String?
  actorEmail String?
  beforeJson Json?
  afterJson  Json?
  createdAt  DateTime @default(now())

  @@index([createdAt])
}
```

注意：
- PostgreSQL 版優先用 Decimal，不再用 Float 表示庫存數量。
- `Item` 的 active-name uniqueness 不建議直接用 `@@unique([name, isActive])`，因為會限制同名停用資料的歷史策略。實作前需明確決定「名稱永久唯一」或用 partial unique index；第一版建議名稱永久唯一，停用後需要重新啟用原品項，不建立同名新 Item。
- `reversalOfMoveId @unique` 用於防止同一交易被 reversal 多次；若 Prisma self-relation 有需要，Codex 應補完整 relation 定義。

# 19. Prisma / Supabase 連線規則

Prisma datasource 使用 PostgreSQL。

不要把 connection string 寫死在 schema。

依最新 Prisma 版本，可能使用 `prisma.config.ts` 管 datasource URL。Codex 必須以專案安裝的 Prisma 版本官方做法為準。

概念上區分：

```text
DATABASE_URL  → Production runtime / serverless pooled connection
DIRECT_URL    → Migration / direct-or-session connection
```

Migration：
- 不在每次 Vercel function request 執行 migration。
- migration 由 deployment workflow / 手動 release step 執行。
- Production migration 前應先有可復原備份策略。

- Auth 成功但 email 非白名單 -> sign out + 顯示拒絕

- 可以先用 Supabase Dashboard / 管理流程處理。
- 若做使用者自助 reset，必須正確設定 redirect URL 與 Email delivery；不要做半套流程。

# 26. 測試要求

至少測試：

1. `3組 × 6 + 4 = 22`。
2. `1盒` 不知道每盒數量 -> NEEDS_REVIEW + null normalizedQty。
3. Opening 40 + OUT 5 = 35。
4. OUT 5 + reversal -> 回 40。
5. Opening 35，stocktake 33 -> ADJUST_LOSS 2。
6. 預設禁止負庫存。
7. 相同 Excel hash 第二次 commit 被阻擋。
8. NEEDS_REVIEW 不加入 current stock。
9. 同品項兩 locations 正確合計。
10. 停用品項不出現在新交易選單，但歷史可讀。
11. 未登入 API 回 401/redirect。
12. 非 ALLOWED_USER_EMAIL 被拒絕。
13. reversal 同一原交易不可建立兩次。
14. 出庫 transaction 在 concurrent request 下不可突破負庫存規則。
15. Excel import commit 失敗整批 rollback。
